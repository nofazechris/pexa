# PrivyPay

Next.js implementation of the **PrivyPay v3** Claude Design project
([source](https://claude.ai/design/p/da964432-ce6a-4a5f-bb9e-2a6f80c3523b)).

A prototype for an AI payment agent: send, request and schedule stablecoin payments by
username, settling on Celo, with the same agent reachable from ChatGPT, Claude and WhatsApp.

```bash
npm run dev
```

## Stack

Next.js 16 (App Router, Turbopack) · React 19 · TypeScript · Tailwind CSS v4 · Geist via `next/font`.

## How the design gets here

The design ships as `design/PrivyPay v3.dc.html` — a single Claude Design artboard: React-flavoured
markup with `{{ }}` bindings, `<sc-if>` / `<sc-for>` control flow and `style-hover` /
`style-focus` / `style-active` attributes, plus a `DCLogic` class holding all the state.

Rather than hand-copying ~1,350 lines of markup, the markup is **transpiled** and the logic is
**ported by hand**:

| Source | Becomes | How |
| --- | --- | --- |
| `<x-dc>` markup | `src/components/screens/*.tsx` | generated by `tools/transpile.js` |
| `<helmet>` CSS + `style-*` attrs | `src/styles/design.css` | generated by `tools/transpile.js` |
| `DCLogic` class | `src/lib/viewModel.ts` | hand-ported to hooks |
| `HERO_BG` canvas engine | `src/lib/heroBackground.ts` | hand-ported to a hook |
| `assets/logo-*.png` | `public/assets/` | copied |

Regenerate the two generated outputs after editing the design file:

```bash
npm run design:build
```

### What the transpiler handles

- `{{ expr }}` in text and attributes → JSX expressions, resolved against the `v` view model
  (`sc-for` loop variables stay in scope and are left bare).
- `<sc-if value>` → a ternary; `<sc-for list as>` → `.map()` inside a keyed `<Fragment>`.
- Inline `style` strings → style objects, camelCased. A repeated CSS property (the design uses
  this to override an earlier shorthand) keeps only the last occurrence, since a JS object
  literal cannot repeat a key.
- `style-hover` / `style-focus` / `style-active` → real CSS classes in `design.css` whose
  declarations carry `!important`, so they beat the element's inline styles. This mirrors what
  the Claude Design runtime (`design/support.js`) does at runtime.
- Attribute case. HTML parsing lowercases attribute names, which would turn `strokeWidth` into
  an invalid `strokewidth` prop, so the original spelling is recovered from the raw source.
- `'Geist'` / `'Geist Mono'` in CSS → `var(--font-geist)` / `var(--font-geist-mono)`, since
  `next/font` generates its own family names.
- `ref="{{ x }}"` resolves against a separate `refs` prop rather than the view model. A DOM
  handle carried on `v` makes the React Compiler lint read every downstream `v.something` as
  a render-time ref access.

### The view model

`useViewModel()` returns the same flat bag of values that the design's `renderVals()` produced,
so the generated components stay a mechanical translation of the markup. Class `setState`
became `useState` with a partial-merge helper, and the three timer lists became refs cleared on
unmount.

Handlers that need to read current state (`runCmd`, `sendNext`, `startSetup`, `cmdConfirm`) are
bound to the committed state inside the `useMemo`, the same way the original class closed over
`this.state` at render time. Only the hero reel's 5.6-second auto-confirm reads through a ref,
because it genuinely needs state from later than the render that scheduled it.

## The hero backdrop

Three stacked canvases behind the hero draw a network of drifting curves, with payment pulses
travelling along them and expanding rings where they land. Each layer parallaxes against the
pointer and the scroll position at its own depth, and the hero reel's own `sending` / `done`
moments push extra pulses through it.

`useHeroBackground` runs the engine only while the landing screen is mounted, and hands the
markup **callback refs** rather than ref objects, for the lint reason above. Frames come from
a rAF loop backed by a 50ms interval watchdog: rAF stalls whenever the page is composited but
not painting (an inactive preview pane, an occluded window), so the watchdog is load-bearing
rather than a quirk of the design host. It stands down while `document.visibilityState` is
`hidden`, so a genuinely backgrounded tab costs nothing, and `prefers-reduced-motion` draws a
single static frame and starts no loop at all.

Per-layer blur is a CSS `filter` on each `<canvas>` element (set once when the canvas is
sized), not a per-frame `ctx.filter` convolution — the compositor blurs the Far and Mid
layers for free instead of the CPU re-blurring the whole canvas on every frame.

## Performance

The two changes that matter for how the page feels:

- **Constant view-model values are built once, not per render.** `renderVals` rebuilds on
  every state change — and the hero typing animation alone fires it ~18 times during boot.
  The two sparkline charts and, especially, the two decorative QR grids (441 elements each)
  never change, so they are computed once at module load (`HERO_CHART`, `QR_SMALL`, …) and
  referenced from the bag rather than reallocated each time.
- **Hero blur moved off the per-frame path** (see above).

Only the active screen is mounted at a time (`PrivyPay.tsx` renders one of four), so the app
never pays to reconcile screens that are off.

## Layout

```
design/            source .dc.html + the vendored Claude Design runtime (reference only)
tools/transpile.js design → JSX/CSS generator
src/lib/           view model (state + derived values) + hero canvas engine
src/components/    PrivyPay root + generated screens
src/styles/        generated design.css
public/assets/     service logos
```

## Notes

- Everything is a front-end prototype: balances, contacts, transactions and the agent's intent
  parsing are all in-memory fixtures. There is no wallet, no network and no persistence.
- `src/components/screens/*.tsx` and `src/styles/design.css` are generated — edit the design
  file and re-run `npm run design:build` instead of editing them directly.
- `npm run lint` reports 9 `no-img-element` warnings, one per service logo. These are 20px
  decorative marks where `next/image` would add more than it saves.
